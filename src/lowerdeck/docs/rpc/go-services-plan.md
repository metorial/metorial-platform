# Go services on lowerdeck RPC — implementation plan

## Goal

Let Go services join the lowerdeck RPC system (`@lowerdeck/rpc-server` / `rpc-client`) as
first-class peers. Each Go service describes its interface in a TypeScript DSL (same style as
the `@metorial/control` specs) and code generation produces:

| From a spec | We generate                                   | Used by               |
| ----------- | --------------------------------------------- | --------------------- |
| Go service  | Go types + `Service` interface + `Register()` | the Go service itself |
| Go service  | TypeScript client (types + `createXClient`)   | TypeScript callers    |
| Go service  | Go client                                     | other Go services     |

Out of scope: a Go client for an existing TypeScript service. TypeScript services infer their
client type from the controller (`InferClient<typeof controller>`), so there is no spec to
generate from. The wire protocol already allows it (the Go client is tested against a real
TypeScript server), so a hand-written Go client is possible if one is ever needed.

Today Go services talk to TypeScript over gRPC + ts-proto (e.g. `oss/src/origin/apps/code-bucket`),
which brings protobuf tooling, a second error model and no request signing. This plan replaces
that for new work.

## What this change already delivers (phase 0)

- **Protocol spec**: [`protocol.md`](./protocol.md). The current TypeScript behavior written down
  precisely: envelope encoding, batch and direct requests, statuses, errors, HMAC and Ed25519
  signatures, retries.
- **Go runtime `ldrpc`** (`oss/src/lowerdeck/go/ldrpc`, module
  `github.com/metorial/metorial-platform/src/lowerdeck/go/ldrpc`, standard library only):
  - `codec.go`: `Marshal`/`Unmarshal`/`Normalize` for the `@lowerdeck/serialize` envelope
    (`time.Time` ↔ `Date`, bigint/map/set/undefined decoding, array and value modes).
  - `server.go`, `handler.go`: `Server` (an `http.Handler`), batch and direct calls,
    per-call status, `Unary[I, O]` typed adapter, `Validator` hook, middleware, `CallInfo`,
    `HMACAuth`, `Ed25519Auth`, custom `Authenticate`, panic recovery, `Mount(mux)`.
  - `client.go`: `Client`, `Call[O]`, explicit `Batch`, HMAC/Ed25519 signing, the TypeScript
    client's retry and deadline policy.
  - `errors.go`: `*Error` with the `@lowerdeck/error` wire shape and all standard constructors.
  - `signature.go`: HMAC `v1` and `ed25519-v1`, sign and verify, JWK parsing.
- **Conformance**: `testdata/vectors.json` (generated by the real TypeScript packages via
  `bun interop/vectors.ts`) and `interop/interop.test.ts` (real TypeScript client → Go server,
  Go client → real TypeScript server, both signature schemes).
- **Codegen target**: `example/bucketrpc/bucketrpc.gen.go`, compiled and tested against the
  runtime (now generated, see below).

The TypeScript client side needs no new runtime: a generated TS client is a generated type
plus `createClient<GeneratedType>(opts)` from `@lowerdeck/rpc-client`, which is what existing
aux-service clients already do with an inferred type.

## Status

Phases 1–3 are done, and the runtime services (`oss/src/products/runtime`: cluster-manager,
networking) are the first users:

- `@lowerdeck/rpc-spec`: DSL, compiler, IR, TS and Go generators with golden tests, and the
  `rpc-spec generate <spec> [--go <dir>] [--ts <file>] [--check]` CLI. `example/bucketrpc` and
  `interop/generated/bucket.ts` are generated from `src/fixtures/bucket.ts`.
- `.idempotent(false)` on a method: the Go client calls it `WithoutRetry()`, the TS client lists
  it in `nonIdempotentMethods` (forcing `retry: false`).
- Validation parity: `Register` passes each input schema to `ldrpc.WithInputSchema`.
  `testdata/validation.json` (209 payloads across every type kind and constraint, produced by
  the `v` validators via `bun run vectors`) is checked by `go test`, and `interop/` compares a
  generated Go server with a TypeScript server on the wire.
- `ldrpc/kubeauth`: TokenReview authentication of projected ServiceAccount tokens (identity
  with pod name/uid, cache, allowlists, net/http middleware), with an opt-in test against a
  real cluster. TS callers use `projectedTokenHeaders(path)` from `@lowerdeck/rpc-client`.
- `ldrpc/otel`: the phase 4 observability item, as its own Go module.

## Architecture

```
            spec.ts  (TypeScript DSL, @lowerdeck/rpc-spec)
               │  compile()
               ▼
          IR (JSON, versioned)  ── checked: names, cycles, reserved fields, wire rules
        ┌──────┴───────────────┐
        ▼                      ▼
  Go generator             TS generator
  <pkg>.gen.go             generated.ts
  types · Service ·        types · XClient type ·
  Register · Client ·      createXClient · error codes
  input schemas
        │                      │
        ▼                      ▼
  ldrpc (Go runtime)       @lowerdeck/rpc-client (unchanged)
        └────── lowerdeck RPC wire protocol (protocol.md) ──────┘
```

The IR is the contract between the DSL and the generators. Generators never import DSL classes;
they read IR JSON. A future generator (e.g. a TypeScript server stub, which would also unlock
TypeScript service → Go client) only needs the IR.

## The DSL (preview)

The spec is an ordinary TypeScript module, so specs can share types with `import`. Builders are
immutable and chainable, like `endpoint(4330).health('/ping')` in control specs. Names follow
`@lowerdeck/validation` where a concept exists there (`optional`, `array`, `record`, `literal`),
but the DSL is its own introspectable type system: `v` validators can't be turned into Go types
(integer, email, length live in opaque modifier functions; literal and enum values aren't exposed).

```ts
// oss/src/code-bucket/spec/src/index.ts
import { error, method, service, t } from '@lowerdeck/rpc-spec';

export let BucketStatus = t.enum(['active', 'archived']).named('BucketStatus');

export let Bucket = t
  .object({
    id: t.string(),
    name: t.string({ minLength: 1, maxLength: 200 }).description('Human-readable name.'),
    status: BucketStatus,
    sizeBytes: t.int({ min: 0 }),
    labels: t.record(t.string()),
    createdAt: t.datetime(),
    archivedAt: t.datetime().nullable()
  })
  .named('Bucket');

export let FileEntry = t
  .union('type', {
    file: t.object({ path: t.string(), size: t.int() }),
    directory: t.object({
      path: t.string(),
      children: t.array(t.lazy(() => FileEntry))
    })
  })
  .named('FileEntry');

let bucketArchived = error({
  status: 409,
  code: 'bucket_archived',
  message: 'The bucket is archived.',
  data: { bucketId: t.string() }
});

let page = <T extends t.Type>(item: T) =>
  t.object({ items: t.array(item), nextCursor: t.string().optional() });

export default service({
  name: 'code-bucket',
  description: 'Stores and serves code bundles for function deployments.',
  go: { package: 'bucketrpc' },
  ts: { client: 'CodeBucketClient' },

  methods: {
    ping: method({
      input: t.void(),
      output: t.object({ ok: t.boolean() })
    }),

    bucket: {
      get: method({
        input: t.object({ bucketId: t.string({ minLength: 1 }) }),
        output: Bucket,
        errors: [bucketArchived]
      }),

      list: method({
        input: t.object({
          status: BucketStatus.optional(),
          cursor: t.string().optional(),
          limit: t.int({ min: 1, max: 500 }).optional()
        }),
        output: page(Bucket)
      }),

      archive: method({
        input: t.object({ bucketId: t.string() }),
        output: Bucket,
        errors: [bucketArchived]
      }).description('Idempotent: archiving an archived bucket returns it unchanged.'),

      files: {
        tree: method({
          input: t.object({ bucketId: t.string(), prefix: t.string().optional() }),
          output: t.object({ root: FileEntry })
        })
      }
    }
  }
});
```

Nested objects under `methods` are namespaces; the method path becomes the wire name
(`bucket:files:tree`), the Go method name (`BucketFilesTree`) and the TS client path
(`client.bucket.files.tree(...)`).

### Type mapping

| DSL                                                       | TypeScript          | Go                                                                | Wire                                                |
| --------------------------------------------------------- | ------------------- | ----------------------------------------------------------------- | --------------------------------------------------- |
| `t.string({ minLength?, maxLength?, pattern?, format? })` | `string`            | `string`                                                          | string                                              |
| `t.boolean()`                                             | `boolean`           | `bool`                                                            | boolean                                             |
| `t.int({ min?, max? })`                                   | `number`            | `int64`                                                           | number, must stay within ±2^53−1                    |
| `t.number({ min?, max? })`                                | `number`            | `float64`                                                         | finite number                                       |
| `t.datetime()`                                            | `Date`              | `time.Time`                                                       | ISO-8601 + `Date` annotation, millisecond precision |
| `t.bytes()`                                               | `string` (base64)   | `[]byte`                                                          | standard base64 string                              |
| `t.json()`                                                | `unknown`           | `json.RawMessage`                                                 | any JSON                                            |
| `t.literal('x')`                                          | `'x'`               | `string` (checked)                                                | as JSON                                             |
| `t.enum(['a', 'b'])`                                      | `'a' \| 'b'`        | named `string` type + constants                                   | string                                              |
| `t.array(T)`                                              | `T[]`               | `[]T`                                                             | array                                               |
| `t.record(T)`                                             | `Record<string, T>` | `map[string]T`                                                    | object                                              |
| `t.object({...})`                                         | `interface`         | `struct`                                                          | object                                              |
| `t.union('type', { a: obj, b: obj })`                     | discriminated union | interface + one struct per variant + wrapper with `UnmarshalJSON` | object with discriminator                           |
| `t.lazy(() => T)`                                         | reference           | reference                                                         | recursion; target must be `.named()`                |
| `t.void()`                                                | `void`              | `struct{}`                                                        | `{}` in, `null` out                                 |

Modifiers on any type: `.optional()` (key may be absent; TS `key?: T`, Go `*T` with
`omitempty`, slices and maps plain with `omitempty`), `.nullable()` (TS `T | null`, Go `*T`),
`.named('Name')`, `.description('...')`, `.deprecated('reason')`, `.example(value)`.

### Compiler rules

`compile()` rejects a spec that would be ambiguous or lossy on the wire:

- Method inputs and outputs are objects, discriminated unions of objects, or `t.void()`. No
  top-level nullable, scalar or array values (protocol §4.4).
- No input may have a top-level `calls` field (protocol §5.3).
- Object keys must not be `$$TYPES$$`/`$$MODE$$`. Method and namespace segments match
  `[a-z][A-Za-z0-9]*` and must not collide.
- Every Go and TS type name must be unique. Anonymous types are named from their position
  (`BucketGetInput`, `BucketListOutput`, `BucketListOutputItem`, `FileEntryDirectory`);
  collisions are an error asking for `.named()`.
- Recursion only through `t.lazy` to a named type.
- `t.int` bounds must lie within the safe-integer range; `.optional()` and `.nullable()` on
  the same field are rejected (Go can't tell absent from null without a wrapper type).

### IR

`compile(spec)` returns plain JSON, versioned independently of the DSL:

```jsonc
{
  "irVersion": 1,
  "service": { "name": "code-bucket", "description": "…", "go": { "package": "bucketrpc" }, "ts": { "client": "CodeBucketClient" } },
  "types": {
    "BucketStatus": { "kind": "enum", "values": ["active", "archived"] },
    "Bucket": { "kind": "object", "fields": [
      { "name": "id", "type": { "kind": "string" } },
      { "name": "archivedAt", "type": { "kind": "datetime" }, "nullable": true }
    ] },
    "BucketGetInput": { "kind": "object", "fields": [
      { "name": "bucketId", "type": { "kind": "string", "minLength": 1 } }
    ] }
  },
  "errors": { "bucket_archived": { "status": 409, "message": "The bucket is archived.", "data": [ … ] } },
  "methods": [
    { "name": "bucket:get", "path": ["bucket", "get"], "input": { "ref": "BucketGetInput" }, "output": { "ref": "Bucket" }, "errors": ["bucket_archived"] }
  ]
}
```

## Generated code (preview)

### Go (server and client in one package)

The full output is `oss/src/lowerdeck/go/ldrpc/example/bucketrpc/bucketrpc.gen.go`. In short:

```go
type Service interface {
	BucketGet(ctx context.Context, in *BucketGetInput) (*Bucket, error)
	BucketList(ctx context.Context, in *BucketListInput) (*BucketListOutput, error)
	// …
}

func Register(srv *ldrpc.Server, impl Service) {
	srv.Handle("bucket:get", ldrpc.Unary(impl.BucketGet, ldrpc.WithInputSchema(schemas.Type("BucketGetInput"))))
	// …
}

const CodeBucketArchived = "bucket_archived"

func ErrBucketArchived(bucketID string) *ldrpc.Error { … }

func NewClient(endpoint string, opts ldrpc.ClientOptions) (*Client, error)
func WrapClient(rpc *ldrpc.Client) *Client

func (c *Client) BucketGet(ctx context.Context, in *BucketGetInput, opts ...ldrpc.CallOption) (*Bucket, error) {
	return ldrpc.Call[Bucket](ctx, c.rpc, "bucket:get", in, opts...)
}
```

Error `data` fields become constructor parameters (pointers when optional); string `reason`,
`hint` and `description` fields map to the standard error fields. Required slices, maps and
bytes carry `ldrpc:"nonnil"` so a nil value is sent as `[]`, `{}` or `""`, as TypeScript
callers expect.

A Go service then needs only:

```go
srv := ldrpc.NewServer(ldrpc.ServerOptions{
	Path:         "/rpc",
	Authenticate: ldrpc.HMACAuth(func(*http.Request) (string, error) { return cfg.RPCSecret, nil }),
})
bucketrpc.Register(srv, &bucketService{db: db})
srv.Mount(mux)
```

### TypeScript client

```ts
// Code generated by @lowerdeck/rpc-spec from code-bucket. DO NOT EDIT.
import { createClient, type ClientOpts, type RpcMethod } from '@lowerdeck/rpc-client';

export type BucketStatus = 'active' | 'archived';

export interface Bucket {
  id: string;
  name: string;
  status: BucketStatus;
  sizeBytes: number;
  labels: Record<string, string>;
  createdAt: Date;
  archivedAt: Date | null;
}

export type FileEntry =
  | { type: 'file'; path: string; size: number }
  | { type: 'directory'; path: string; children: FileEntry[] };

export type CodeBucketClient = {
  ping: RpcMethod<void, { ok: boolean }>;
  bucket: {
    get: RpcMethod<{ bucketId: string }, Bucket>;
    list: RpcMethod<BucketListInput, { items: Bucket[]; nextCursor?: string }>;
    archive: RpcMethod<{ bucketId: string }, Bucket>;
    files: { tree: RpcMethod<BucketFilesTreeInput, { root: FileEntry }> };
  };
};

export let codeBucketErrorCodes = ['bucket_archived'] as const;

export let createCodeBucketClient = (opts: ClientOpts) => createClient<CodeBucketClient>(opts);
```

`RpcMethod<I, O>` (`((input: I, opts?) => Promise<O>) & { getFull }`) is the only
`@lowerdeck/rpc-client` change: today that shape lives in `rpc-server`'s `InferClient`, and a
client package must not depend on the server package. It is purely additive.

## Validation

TypeScript handlers validate input with `@lowerdeck/validation` and answer `400 invalid_data`
with an issue list (`code`, `message`, `path`). Go services must answer the same way, so clients
can't tell which language served them.

Plan: the generator emits each input type's IR as a compact schema value, and `ldrpc` gains a
small schema interpreter that checks the decoded JSON tree **before** unmarshalling: presence of
required keys (which `encoding/json` can't detect), types, enum and literal values, int
bounds, string length/pattern/format, union discriminators. It produces the same issue codes and
paths as `v` (`invalid_type`, `too_small`, …). Validation logic then lives once, in the runtime,
not in generated code. A parity test feeds the same invalid payloads to a `v` validator and the Go
interpreter and compares the issues.

Outputs aren't validated at runtime (TypeScript doesn't validate them either); generator
golden tests and the Go type system cover them.

## Where things live

| What                               | Where                                                                                                                 |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Protocol spec, this plan           | `oss/src/lowerdeck/docs/rpc/`                                                                                         |
| Go runtime                         | `oss/src/lowerdeck/go/ldrpc` (done)                                                                                   |
| DSL, IR, compiler, generators, CLI | `oss/src/lowerdeck/packages/rpc-spec` → `@lowerdeck/rpc-spec`                                                         |
| A service's spec                   | `oss/src/<service>/spec` (private TS package with a `generate` script)                                                |
| Generated Go                       | `oss/src/<service>/service/rpc/<pkg>/<pkg>.gen.go`. Not under `internal/`, so other Go modules can import the client. |
| Generated TS client                | `oss/src/<service>/clients/<service>/src/generated.ts`, re-exported by the existing client-package pattern            |

Generated files are committed: Go builds must not need Bun, and reviewers should see interface
changes in diffs. `rpc-spec generate --check` runs in CI and fails if anything is out of date.
After regenerating, the TS client package is rebuilt (`bun run build`), as for every aux
service client today.

## Phases

### Phase 1 — DSL, IR and compiler (`@lowerdeck/rpc-spec`)

- `t.*` builders, `method`, `error`, `service`; immutable, each with `toRaw()`.
- `compile()` → IR with all compiler rules above; errors name the offending path
  (`methods.bucket.get.input.calls`).
- IR TypeScript types exported for generators.
- Tests: one valid spec per type kind, one failing spec per compiler rule.

_Done when_ the preview spec above compiles to the IR shown and every rule has a failing test.

### Phase 2 — generators and CLI

- TS client generator first (types only; smallest, unblocks TS consumers). Add `RpcMethod` to
  `@lowerdeck/rpc-client`.
- Go generator: named and anonymous types, enums with constants, unions (interface + variants +
  wrapper with `MarshalJSON`/`UnmarshalJSON`), `Service`, `Register`, error constructors,
  `Client`. Go names use initialisms (`bucketId` → `BucketID`); the JSON tag keeps the wire name.
  Output passes `gofmt`.
- CLI: `rpc-spec generate <spec> --go <dir> --ts <file> [--check]`.
- Golden-file tests for both generators. The Go golden output must compile and pass a test
  equivalent to `example/bucketrpc` (which the generated file then replaces).
- Interop test extended: generated TS client against a generated Go server.

_Done when_ `example/bucketrpc` is generated instead of hand-written and interop passes through
the generated clients.

### Phase 3 — validation parity

- `ldrpc` schema interpreter and `Unary(fn, schema)`; generator emits schemas.
- Parity test against `@lowerdeck/validation` for every type kind and constraint.

_Done when_ a malformed payload gets byte-identical `errors` arrays from a TS and a Go server.

### Phase 4 — pilot service

- Move one Go service onto ldrpc. Candidates: a new service, or `code-bucket` (gRPC +
  ts-proto today) behind a feature flag with both transports running during cut-over.
- Wire `control` (dev env, endpoint and health), signing secrets through `settings-and-env`
  and CDK, and add `go test ./...` for `ldrpc` and the pilot to CI.
- Observability (done, `ldrpc/otel`): `otelhttp` around `Server` and the client transport
  (which injects `traceparent`), a span per call on both sides via middleware and
  `ClientOptions.Intercept`, structured logs from `OnCall`/`OnError`.

_Done when_ the pilot runs in staging with TypeScript callers using the generated client.

### Phase 5 — documentation and conventions

- Add `@lowerdeck/rpc-spec` and `ldrpc` to the `lowerdeck` skill's `references/packages.md`.
- A "Go services" section in `codebase-structure` (layout, generate/check, rebuild client).
- Compatibility rules in `rpc-spec`'s README (below).

## Compatibility rules for spec changes

Safe: adding a method; adding an optional input field; adding an output field; adding an
error code; widening a constraint. Go servers ignore unknown input fields and both clients
ignore unknown output fields.

Breaking: removing or renaming anything; making an optional input field required; changing a
type; narrowing a constraint; adding an enum value to an _output_ (TS clients' exhaustive
switches go stale; Go clients tolerate it since enums are `string` types). Breaking changes go
through add-new → migrate callers → remove-old, because services and callers deploy
independently.

## Decisions to confirm

1. **Runtime location and module path.** `oss/src/lowerdeck/go/ldrpc`, module
   `github.com/metorial/metorial-platform/src/lowerdeck/go/ldrpc` (go-gettable from the OSS repo;
   consumers in the monorepo use a `replace` directive). Alternative: a short vanity path like the
   existing `github.com/metorial/object-storage/clients/go`.
2. **CI for Go.** The Bun workspace doesn't cover Go modules. Proposed: a `package.json` with
   `"test": "go test ./... && bun test interop"` beside `go.mod` so Turbo picks it up, which
   needs Go on CI images.
3. **`optional` + `nullable` together.** Rejected for now. Alternative: generic
   `ldrpc.Optional[T]` that tracks absent/null/value.
4. **`bigint`.** Deferred. `ldrpc` already decodes it; encoding needs a `t.bigint()` ↔
   `*big.Int` mapping.
5. **Spec-first TypeScript services.** A TS server-stub generator from the same IR would unlock
   TypeScript service → Go client and make specs the norm everywhere. Not planned; the IR is
   designed so it can be added.
